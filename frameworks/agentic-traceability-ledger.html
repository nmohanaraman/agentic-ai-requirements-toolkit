F-05 · Agentic AI Requirements Toolkit

Agentic Traceability Ledger

From requirement to runtime evidence: proof that everything the agent did was specified.

01 · What problem it solves

Classical traceability demonstrates that everything specified was built. Agentic systems demand the reverse claim — that everything the agent did was specified — because behavior cannot be exhaustively verified before deployment; verification continues in production. The ledger is what converts regulatory text into analyst work products: the EU AI Act's logging obligations and the NIST AI RMF's measurement function both presuppose a chain from intended to tested to observed to recorded behavior, yet neither says who builds it.

02 · How it works

Two linked registers extend every requirement. Ledger A (design-time): requirement → policy or control source → pre-release evaluation → acceptance threshold → owner. Ledger B (run-time): requirement → runtime signal → alert threshold → required evidence record → evidence location and retention → review frequency. A minimum runtime evidence record captures: event ID, timestamp and agent version, triggering input, the boundary rule that authorized or blocked the action, tools invoked and results, state before and after, any human decision, and final outcome. It can begin as three added columns on the existing requirements register — no tool purchase required.

03 · Worked example

Retail returns agent, one ledger row end to end:

R-014Every auto-issued refund must be reconstructable: triggering request, eligibility evidence, boundary rule, amounts before/after, and notification sent
Control sourceFinance policy FP-7 (payment reversals); consumer-protection audit requirement
Pre-release evalReplay 200 historical returns; 100% must produce a complete evidence record
Runtime signalEvidence-completeness check on every RefundExecute call; alert on any missing field
Evidence & retentionAppend-only refund-evidence store; 7-year retention; finance read access
ReviewWeekly sample of 25 records reconstructed by an analyst who did not build the agent

Functionally, this row is the difference between a pilot the audit function tolerates and one it sponsors.

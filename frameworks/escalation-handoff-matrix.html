F-04 · Agentic AI Requirements Toolkit

Escalation & Handoff Matrix

Replaces “human in the loop” — the most cited and least specified phrase in AI governance — with routing rules.

01 · What problem it solves

A requirement that says “a human reviews agent decisions” is unverifiable until it states which decisions, which human, with what information, and with what authority. The matrix classifies every agent action along two axes — business impact and reversibility — and assigns each class an oversight mode. Equally important is the handoff itself: a handoff without a specified payload merely relocates the failure from the agent to an uninformed human.

02 · How it works

Reversible / compensableIrreversible
High impactNOTIFY + UNDO WINDOW — agent may act if evidence and rollback are definedFULL ESCALATION — human decides; agent assembles the decision package
Low impactAUTONOMOUS + LOG — run within approved boundariesAPPROVAL QUEUE — human approval before execution

For every escalation, specify the handoff payload: recipient role, context, evidence, enumerated options, the agent's recommendation with stated confidence, decision deadline, the default on timeout, and where the human decision is written back. Two measurable requirements give the matrix teeth: escalation coverage (fraction of novel-scenario classes that correctly route to a human in test suites) and approval latency (the SLA for MUST ASK decisions — without it, queue pain quietly pressures thresholds upward).

03 · Worked example

Retail returns agent, four action classes:

Action classImpactReversibilityModeTimeout default
Refund ≤ $75 in policyLowCompensableAutonomous + log—
Refund $75–$400HighCompensableApproval queue (supervisor, 4h SLA)Hold; customer notified of review
Restocking-fee waiverLowIrreversibleApproval queue, daily batchDeny; re-queue next day
Suspected-fraud closureHighIrreversibleFull escalation with decision packageNo action; case stays open

The escalation payload for fraud cases enumerates exactly three human options — approve refund, deny with reason code, request more evidence — and requires the decision written back to the case record, closing the loop the Traceability Ledger audits.

F-07 · AI-Augmented BA Operating Toolkit

Task Triage Matrix

For each task: augment, automate with governance, protect, or elevate.

01 · What problem it solves

Knowing your pyramid level is necessary but not sufficient. Every task needs a disposition, and a two-axis grid forces it: AI capability (how well can current tools perform this without human correction?) against stakeholder trust (must a human be accountable — is it client-facing, regulatory, or high-consequence?). The matrix is a discussion trigger, not an automatic policy engine; the point is not the exact split, it is that the conversation happens before the automation does.

02 · How it works

Low AI capabilityHigh AI capability
High trust requiredELEVATE — retain senior human ownership; never automateAUTOMATE — only with governance: audit trail, escalation rule, accountable owner
Low trust requiredPROTECT — keep human for now; capability is not readyAUGMENT — AI drafts, classifies, summarizes; human reviews

Anything landing in AUTOMATE triggers a documented governance gate before proceeding: approved data and tool access, an accountable human owner, an error threshold, an escalation path, retained audit evidence, and a tested rollback method. Each entry also records the failure mode to watch — the input to the 5-Day Sprint's pilot design.

03 · Worked example

The logistics analyst triages a 40-item backlog in one grooming session. Representative rows: sprint meeting summaries — capability high, trust low → AUGMENT. Duplicate-shipment detection in the order warehouse — capability high, trust high → AUTOMATE, gated on an error threshold and weekly audit sample. New customs-regime onboarding analysis — capability low, trust low → PROTECT. Carrier data contract negotiation and any regulator-facing escalation → ELEVATE, staffed with the most senior analyst in sprint planning. The AUTOMATE entries are the only ones that require a signed governance decision before work starts.

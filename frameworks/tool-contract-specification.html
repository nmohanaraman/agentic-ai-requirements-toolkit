F-03 · Agentic AI Requirements Toolkit

Tool Contract Specification

Every API, query, or system call the agent can invoke is a capability grant — and each grant gets a contract.

01 · What problem it solves

Agents act through tools. A tool the agent can invoke is not an implementation detail; it is a delegation of capability, and misuse propagates at machine speed. Interface specification is discipline the profession already owns; the tool contract extends it with two fields traditional interface specs omit — reversibility and blast radius — because those two fields drive escalation design and reveal which tools must be redesigned before an agent may hold them.

02 · How it works

One contract per tool, covering: purpose (one sentence a risk reviewer can understand); inputs and validation; preconditions; side effects, including downstream notifications; reversibility class (reversible / compensable / irreversible); rollback or compensation method and window; blast radius stated concretely, not as “data quality impact”; usage constraints (rate, volume, time windows); prohibited use; logging and evidence; and escalation triggers. Each contract is approved by the business owner, engineering, and risk. A tool with an undefined blast radius or reversibility class should not be available to the agent. A companion inventory view ranks all tools by impact and privilege and asks the reduction questions: can it be read-only, can it write to staging, can volume be capped?

03 · Worked example

Retail returns agent — contract for the highest-risk tool:

ToolRefundExecute (payments platform API)
PurposeIssues a refund against a captured payment for a verified return
PreconditionsReturn status = RECEIVED; boundary rule AB-001 or approved AB-002 satisfied; idempotency key present
Side effectsPayment reversal; order-state change; customer notification email; finance ledger entry
ReversibilityCompensable — re-charge possible within 72h with customer consent; effectively irreversible after settlement
Blast radiusWorst plausible misuse: bulk erroneous refunds within one rate window (≤ 60 × $75 = $4,500/hour cap)
Constraints≤ 60 calls/hour; business hours only for AB-002 class; no batch mode
Escalate whenAPI declines twice; amount/currency mismatch; duplicate-refund detection fires

Drafting the six contracts converted two proposed direct-write tools into staging writes a human promotes — from irreversible to compensable — before any model was selected.
